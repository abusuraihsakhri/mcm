# MCM audit — 24 September 2026

## Verdict

MCM is a substantial research prototype, but it is not ready to support claims of sound semantic equivalence, complete historical reconstruction, or demonstrated agent benefit. The test suite provides useful internal coverage; reproduced counterexamples expose gaps in the properties it currently checks.

**Scope:** current GitHub main `a05de77`, Python package, canonical storage, ingestion, equivalence, retrieval and context assembly, benchmark and agent-study methods, API/MCP boundaries, packaging, CI, privacy checks, documentation, and GitHub Pages. This is a source review with targeted executable counterexamples and local UI validation, not a penetration test or a rerun of the research studies. The starting local checkout was 20 commits behind; it was fast-forwarded before changes. The pre-existing `.gitignore` edit was preserved.

## Priority findings

| Priority | Finding | Evidence and consequence | Status / required action |
| --- | --- | --- | --- |
| P1 | Normal-form equality can falsely establish semantic equivalence | `mcm/equivalence/normalise.py`, `_rename_map` and `_tokens`, normalize identifiers without resolving their binding. `def f(x): return obj.x` and `def f(y): return obj.y` produce equal normal-form digests. `mcm/equivalence/engine.py`, `_semantic`, promotes matching forms to semantic equivalence. Distinct attribute reads need not behave alike. Keyword parameter renaming and Python introspection also prevent an unrestricted semantic guarantee. | **Open.** Define the equivalence domain and observable behavior, make normalization scope-aware, and refuse semantic conclusions without adequate proof. Reassess existing normal-form classes after a fix. |
| P1 | Reappearing relations erase historical gaps | `SQLiteStore.put_relation` retains the original `valid_from` but overwrites `valid_until`. Reproduction: insert at Jan 1, close at Jan 2, query Jan 3 → absent; reinsert at Jan 4, query Jan 3 → present. One row cannot represent disjoint intervals. | **Open.** Version relation occurrences or store separate validity intervals, migrate existing databases explicitly, and test present→absent→present histories. |
| P1 | Historical relations are not a historical object snapshot | `objects` has one row per ID; `put_object` overwrites properties/state. Old relations can therefore be combined with the latest symbol text and fingerprint. Reopening relations also overwrites supporting evidence IDs. | **Open.** Version objects/evidence associations or narrow the time-travel contract. Validate replay against actual Git snapshots. |
| P1 | Benchmark intervals use the wrong independent unit for pooled task families | `_tasks_for` creates retrieval, planning, debugging and impact tasks from one commit. `runner.compare` calls `paired_bootstrap` over the resulting task list. Pairing systems preserves within-task comparison but does not account for dependence among tasks from one commit. | **Open.** Resample commits with all their tasks together; report independent commit counts. For cross-repository inference, account for repository clustering. Existing intervals may be too narrow; exact changes in verdicts are unknown. No statistics were recomputed in this audit. |
| P1 | Oracle labels are an order-dependent repair heuristic | `scripts/oracle_tasks.py` keeps each candidate file that lowers the failure count before testing the next candidate. This is cumulative greedy repair, although `docs/evaluation.md` describes testing each other file alone. Jointly necessary repairs can be missed; failure counts also hide changes in which tests fail. | **Open.** Record failing test IDs, reset to the same broken baseline for individual interventions, separately evaluate joint repairs, and regenerate labels before causal claims. Current labels support a narrower operational interpretation. |
| P1 | REST requests share a mutable, unsynchronized connection | `create_app` closes over one `SQLiteStore`; synchronous routes can execute concurrently. The connection uses `check_same_thread=False` and a shared `_bulk_depth`, without request-level transaction isolation. A reader may observe a partial ingest; concurrent mutations can share a transaction. | **Open.** Serialize whole store operations or use properly isolated connections and transactions, with concurrency regressions. Disabling SQLite's thread check is not request isolation. |
| P2 | Valid JSON with the wrong shape can kill MCP | A scalar/array reaches `handle`; its `.get` fails, and the exception handler calls `.get` again. A subsequent valid request is never served. Initialization notifications also received responses. | **Fixed in this change.** Validate the JSON-RPC envelope, params and tool argument container; keep notifications silent. Nine new stream/protocol regression cases pass. |
| P2 | REST is a local trusted-process interface, not a secured hosted API | No authentication or authorization is configured. Ingestion roots are optional; an exact directory deny-list does not deny arbitrary descendants. Indexing reads source into the store and endpoints expose it. Root validation is not an authentication boundary. | **Open deployment constraint.** Keep loopback binding and trusted clients. A network deployment needs authentication, explicit roots, resource limits and concurrency repair. No public API was exposed during this audit. |
| P2 | Evaluation provenance is insufficient for exact independent reproduction | `evaluation_suite.py` clones current upstream heads and resumes based only on result filename. `run_json` rounds scores and omits a complete dependency/model/config manifest and full task truth manifest. No raw retrieval sweep result files are tracked in this checkout; oracle task/trial JSON is present. | **Open.** Pin repository revisions and model revisions, retain full-precision per-task data and truth, record software/configuration hashes, and refuse stale resumes. Archived release assets were not independently audited. |
| P2 | Non-separation is presented as approximate equality | `runner.verdict` returns “approximately equal” both for negligible estimates and for intervals crossing zero. Neither is an equivalence test. The portal previously shortened this to “level.” | **Public wording qualified.** Historical tables remain identifiable as historical output; runner and reports still need a distinct inconclusive category and prespecified equivalence margin if equivalence is the estimand. |
| P2 | Claims exceed what the evaluation measures | Co-change does not establish causal breakage. File-selection recall is not repair success. A null finding is not proof of no effect. Shared token estimation does not ensure equal bias for chunks versus definitions. The reported 0.88 precision is 42/48 predictions among 685 testable observations, not a universal reliability estimate. | **Qualified on the portal and in the methods audit note.** Reassess headline conclusions after clustered analysis and oracle validation. Add uncertainty and explicit denominators to future prediction reports. |
| P2 | HTML audit could report defects and still pass CI | Previous `scripts/audit_html.py` printed missing IDs and handler warnings without failing. It did not check labels, duplicate IDs or local references. | **Fixed.** Audit now returns nonzero on detected defects and checks those additional cases. This static check is not a substitute for browser testing. |
| P2 | Mobile and assistive-technology access was incomplete | Navigation vanished below 980px; visual control labels were unassociated spans; graph content was canvas-only; small low-contrast labels impeded reading. | **Fixed in the redesign.** Persistent wrapping/scrolling navigation, associated labels, clearer typography, text graph relationships, and keyboard-visible focus. Full screen-reader certification was not performed. |
| P3 | The graph continuously animated and math retried indefinitely | An unconditional animation loop ran even when the graph was offscreen. Missing KaTeX caused unlimited retry timers. | **Fixed.** Static draggable graph with event-driven repaints; bounded math initialization. The page remains dependent on third-party font/math assets for enhanced presentation. |
| P3 | Documentation and operational maturity lag implementation | Evaluation limitations said contradiction/memory-update code did not exist, although both are implemented. README described two scored repositories after later sweeps. Dependencies have broad ranges; no reproducible lock or multi-version/OS test matrix is present. | **Stale statements corrected; environment reproducibility remains open.** Versioned release and Apache-2.0/CITATION metadata are present in current main. |

### Additional measurement cautions

`score_ranking` divides hits by `len(top)` rather than the fixed K when a system returns fewer than K results. This is precision among returned items, not conventional fixed-denominator Precision@K. Systems that abstain or return fewer results can appear more precise; report returned counts and a fixed-K sensitivity analysis. MRR is computed over the full ranking, unlike Recall@K. These choices should be explicit wherever the metrics are compared.

## Strengths worth preserving

- A coherent canonical store with typed records, evidence and rebuildable retrieval projections.
- Historical holdout construction reads Git blobs at a horizon rather than indexing the current checkout; tuning repository separation is explicit.
- Baseline tuning, embedding-provider sensitivity and negative results are documented.
- Tests cover many reasoning, storage, MCP and API behaviors; CI includes build and dependency checks with pinned action revisions.
- Default core indexing does not call a hosted language model. External-provider experiments are separate. Local credentials and manuscript directories are ignored; the targeted scan of tracked files found no matching private-key/API-token patterns. This is not a guarantee that all private data or Git history are clean.
- Semantic questions the optional solver cannot answer often return UNKNOWN; this conservative design should also apply to unsound normalization shortcuts.

## GitHub Pages redesign

The existing labs, section IDs, light/dark control, citation and release attribution remain. The revised page uses a compact slate/teal research layout, separates implementation from empirical evidence, presents evidence before the labs, surfaces methodological caveats, and retains all simulations as explicitly illustrative fixtures. CSS is extracted to `site.css`; canonical/social metadata and a local SVG icon are added. No framework or runtime dependency is added.

## Validation and limits

- Full current test suite: **538 passed**, with two existing FastAPI/Starlette deprecation warnings.
- MCP targeted tests: **29 passed**, including nine added protocol/stream cases.
- Package wheel built successfully; `pip check` found no broken requirements; source compilation passed.
- HTML audit: zero errors. A deliberately invalid fixture returned exit code 1 for duplicate IDs, an unlabeled control and a broken anchor.
- Browser checks: 320, 390, 768 and 1440-pixel widths; no document overflow after repair. Light/dark themes, visible keyboard focus, every select option, keyboard budget limits and the illustrative API response were exercised. All 20 input/select controls have labels; the graph has 16 text relationships. No browser errors were recorded in these checks.
- Executable counterexamples reproduced the temporal gap defect and a false `SEMANTIC/EQUIVALENT` verdict.
- The supplementary agent walkthrough reached an optional model download that failed TLS certificate verification. The walkthrough was stopped during repeated download retries. GPU/model-download validation is therefore incomplete; certificate verification was not bypassed.
- Dependency consistency was checked, but a fresh vulnerability-database scan was not run locally. CI has a dependency-audit step. Historical statistical estimates are retained as reported, not recalculated. No new research performance, causal effect, or equivalence claim is asserted. The expensive repository sweeps, paid model-provider experiments, archived release assets, complete Git-history secret scan and public deployment are outside this local verification.

## Recommended repair order

1. Remove false semantic guarantees and implement interval/object versioning with a migration plan.
2. Fix REST concurrency before any multi-client use.
3. Validate oracle interventions, then rerun commit-clustered analyses in R with a frozen manifest. Keep old outputs explicitly versioned.
4. Publish full evaluation inputs and outputs appropriate for sharing, and distinguish inconclusive from equivalent throughout generated reports.
5. Add regression cases for each counterexample and a reproducible environment before promoting the prototype to a stable release.
